## 작업 지시

<!--
작업 대행 건일 때만 쓴다. 아니면 이 섹션을 통째로 지운다.

티켓 내용을 항목으로 옮겨 적는 것은 작업 지시서가 아니다. 그럴 거면 티켓을 보는 게 낫다.
**실행하는 사람이 이것만 보고 끝낼 수 있어야** 한다.

규칙 (playbooks/ticket-outputs.md):
  - 조회부터 시작한다. 티켓은 서버 이름을 주지 리소스 ID를 주지 않는다
  - 변수를 한 번 세팅해서 이후 블록이 복붙으로 돌아가게 한다
  - 바꾸기 전에 현재 상태를 파일로 남긴다
  - 변경 명령에는 [변경] 을 붙인다. 에이전트는 조회만, 변경은 사람이
  - 마지막은 검증 명령
  - 명령어 옵션은 공식 문서로 확인하고 쓴다. 기억으로 쓰지 않는다
-->

전제: (계정·리전이 요청에 없으면 여기에 적고 1번에서 확정한다)

1. 어느 계정에 붙었는지 확인한다

   ```bash
   aws sts get-caller-identity --profile "$PROFILE" --output table
   ```

2. 이름으로 실제 대상을 찾는다

   ```bash
   # 조회 명령
   ```

3. 확인한 값을 변수에 넣는다 — **이 줄만 고치면 아래는 그대로 실행된다**

   ```bash
   TARGETS=()
   PROFILE=csg-<고객사>
   REGION=ap-northeast-2
   ```

4. 현재 상태를 파일로 남긴다 — **되돌릴 근거**

   ```bash
   # describe ... > /tmp/<번호>-before-....json
   ```

5. 기존 설정과 충돌하는지 본다

   ```bash
   # 조회 명령
   ```

6. **[변경]** 실제로 바꾼다 — 사람이 실행

   ```bash
   # 변경 명령
   ```

7. 적용됐는지 확인한다

   ```bash
   # 검증 조회 명령
   ```
