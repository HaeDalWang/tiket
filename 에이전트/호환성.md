# Multi-Agent Compatibility

## Canonical rules and adapters

- Always-on authority and safety contract: root `CLAUDE.md`
- Selective loading contract: `에이전트/작업_라우터.md`
- Codex/Hermes entry point: root `AGENTS.md`
- Claude Code entry point: root `CLAUDE.md`
- Kiro entry point: `.kiro/steering/00-repository-rules.md`
- Shared capability mapping: `에이전트/기능_카탈로그.md`

Adapters exist only to bridge auto-loading differences. Do not copy customer data, long procedures, or policy source material into an adapter.

## Shared task-start sequence

1. Read the compact root `CLAUDE.md`.
2. Classify through `에이전트/작업_라우터.md`.
3. Load the ticket's `current.md`, selected `evidence.md` sections, and only the policy/capability/playbook modules selected by that route. Keep `history.md` unloaded unless historical reconstruction is required.
4. Gather evidence and prepare a draft at the routed assurance tier.
5. Normalize semantics in a Decision Packet, then create a Reply Brief before prose.
6. Use full evidence, PoC, contract, or change gates only when the route requires them.

## Concurrent work

- Do not let two agents modify the same ticket file concurrently.
- Default to sequential handoff: investigation is appended before a reviewer reads it.
- Use a ticket-specific branch or worktree only when true concurrent work is needed.
- Agents must not commit, push, or merge automatically unless the user explicitly assigns that action.

## Minimum handoff state

- Customer and ticket path
- Current status and last completed stage
- Latest Decision Packet v2 JSON and Reply Brief v2 JSON; preserve earlier revisions
- Verified evidence and unresolved items
- `current.md` and `evidence.md` pointers; `history.md` remains on-demand
- Tools used and observation time
- For a PoC: repository, branch, commit, and result document
- One clearly scoped next task

Transfer verified repository state, not an entire session transcript.
