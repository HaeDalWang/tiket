# Task Router

Classify first, then load only the listed modules. Never load every policy, playbook, ticket, or skill by default.

## Universal

- Customer ticket: read the profile, then the matching ticket directory's `current.md`. Read only relevant sections of `evidence.md`. Do not read `history.md` unless reconstructing a changed decision, actual sent/customer response, dispute, or historical thread. Record only de-identified context.
- Policy: search `회사규정/_라우팅.md`; read only matching cards. A `draft` card cannot create a commitment or authorize action.
- Capability: select through `에이전트/기능_카탈로그.md`; verify runtime state before use.
- Use official/current evidence for load-bearing claims. Prior replies are history, not proof.
- Reuse confirmed evidence already recorded in the same ticket when claim, target, and source remain applicable and no conflict exists. Re-fetch only for a new claim, missing support, conflict, changed target/version, or explicit freshness requirement.
- Before any new or revised customer draft, register investigation items with stable `[F#]`, `[H#]`, and `[U#]` IDs; append the latest Decision Packet v2 JSON from `템플릿/결정_패킷.md`; then append a Reply Brief v2 JSON from `템플릿/회신_브리프.md`. Draft prose only from selected IDs. Preserve earlier packet, brief, and reply revisions.

## Route

| Tier | Trigger | Load |
|---|---|---|
| `quick` | General specification or documentation lookup; no live customer state, exact cost, contract, security decision, or mutation | Customer core profile when applicable; capability catalog; official source. Apply the compact checks in `플레이북/근거_검증.md` sections 0, 2, 4, and 7. |
| `standard` | Customer configuration, troubleshooting, recommendation, or cost optimization without a customer-facing figure | `quick` inputs plus matching policy cards, similar tickets, and the full `플레이북/근거_검증.md`. |
| `high-risk` | Credentials/PII sharing, exact cost or contract claim, incident, production change, or irreversible action | `standard` inputs plus the relevant specialized playbook. For changes use `플레이북/인프라_작업_프로세스.md`; for PoC use `연계/README.md`. Stop at the human approval boundary. |

## Output modules

- Reply drafting: `플레이북/회신_작성_규칙.md`
- Reply presentation profiles: `플레이북/회신_스타일.md`
- Semantic convergence: `템플릿/결정_패킷.md`
- Audience and style adaptation: `템플릿/회신_브리프.md`
- Customer/profile fields: `템플릿/고객_프로필.md`
- Ticket current state: `템플릿/티켓.md`
- Ticket evidence registry: `템플릿/티켓_근거.md`
- Ticket append-only history: `템플릿/티켓_이력.md`
- Multi-agent handoff: `에이전트/호환성.md`
- Known traps: search `플레이북/함정/`

Load a local skill only when its trigger directly matches the task and it adds procedure not already supplied by these repository modules. Do not load a broad or merely adjacent skill.
